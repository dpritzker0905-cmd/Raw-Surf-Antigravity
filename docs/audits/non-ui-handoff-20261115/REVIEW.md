## Review disposition

**CBR-01: retain the exact-source, one-use design, subject to implementation review and later separate qualification.** `source_catalog.py` derives inspection-only expected code from the verified wheel under the pinned target compiler. `attestation.py` retains the actual import exec code, module/helper/global/zip-loader identities and direct initializer caller. It retires the capability before checking return/cleanup, records API attempts separately from outcomes and leaves kernel telemetry null. No actual code fingerprint or Linux native-call binding was derived here.

**CBR-02: propose a distinct negative-only resolution contract; adoption remains false.** The original parent initializer's optional import is unreachable through the old fatal import denial. The draft permits one metadata lookup only from its attested source context. A scoped first finder asks only reviewed normal resolvers, with compile/exec/import fenced during resolution. Any spec, unknown resolver, changed search surface, lookup error, repeat or wrong caller terminates. Only all-None results produce an actual `ModuleNotFoundError` that the unchanged upstream source catches. It never returns a module spec, stub, loader or module. This is a new permission; the earlier proposal's claim of no import-rule expansion must not be applied to this combined draft.

**Do not request runtime qualification or construction execution for v1.** Source review exposed a deterministic compatibility blocker: the exact wheel's `pip/_vendor/urllib3/packages/six.py` installs `_importer` in `sys.meta_path` at line1076. That occurs through the parent initializer's dependency imports before its optional import at line27. The draft's frozen resolver tuple deliberately rejects this unbound addition. It must not be solved by accepting whichever finders happen to exist. A later revision needs exact-source attestation of this registration and object, its method code, state, order and lifecycle, with no alternate provider fallback. Other dynamic resolver changes, if found, need the same explicit treatment. CBR-02 is therefore **open**, not fixed.
