## Owned behavior

The new owner APIs list only the authenticated account's tickets, check owner and ticket together before reading a conversation, and return only clearly public messages. Internal notes, staff identifiers/assignment and attachments are not returned. User reply requests forbid extra fields and cannot select internal-note mode, priority or status. User messages retain current ticket lifecycle; only existing staff behavior changes lifecycle. Existing creation is reused with an optional owner-bound request ID. There is no email-response ingestion.

Staff and owner reply request IDs bind ticket, sender and exact content/note intent. A repeat returns the original message; conflicting reuse409. The admin UI retains a request ID for the same draft object across failed retries; a changed text/note intent gets a new ID. Ticket creation also returns its original number/id for the same owner-bound request and rejects changed intent. Legacy callers without request IDs retain their existing behavior and do not gain request-level retry guarantees. Native unique constraints arbitrate insertion; no schema change.

Only a newly stored public staff reply creates an owner notice. Its generic title/body and JSON `{ticket_id,message_id,recipient_id}` carry identifiers rather than support content. Existing messages notification preference gates the notice; email_messages is opt-in, absent preference row defaults false. Eligible email uses the existing transactional outbox with a message-derived idempotency key and ticket UUID only. Disabled/unconfigured/rate-limited/suppressed mail does not discard the in-app reply. Queue/database exceptions roll back message, notice, outbox and lifecycle together. Unknown commit acknowledgement is not automatically replayed; a keyed retry finds the original.

The support template has a generic subject and message, an authenticated `/support/tickets/<UUID>` link and a notice to reply in-app. No subject-derived details, response text, attachments, names or auth tokens are included. The provider adapter omits configured Reply-To for this template. No inbound support mail parser or second conversation is introduced. This remains low-priority mail under existing delay, suppression, rate limit, daily-cap and retry controls; it renders separately so its CTA remains its own ticket, rather than being folded into a generic digest. The existing sweeper is reused; request handlers perform no provider I/O. All actual tests use fake senders/transports.

Priority edits now compute SLA as original created_at plus the new priority's existing1/4/24/72-hour duration. Editing time never becomes a new origin. Creation, descriptions, messages and existing resolution/response fields remain unchanged; updated_at records the edit. Missing creation time409 requires review instead of inventing a fresh clock. Existing closed/reopened status policy and metric cohort semantics remain unchanged.
