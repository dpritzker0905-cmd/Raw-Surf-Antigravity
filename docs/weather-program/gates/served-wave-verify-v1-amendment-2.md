# Amendment 2 to served-wave-verify-v1 (the #1199 LOCKED holdout and the fit-used tags)
Stamp: 2026-11-23. This is the condition the director relayed from the advisor's #1199 limit 1, which must be met before `SERVED_WAVE_VERIFY` is set. It was written before any record exists: nothing has been collected and no score has been read. Where this file differs from `served-wave-verify-v1.md` (#1168) or amendment 1 (#1177), this file holds.

**Why.** #1199 (served-wave-skill-v1, section 1a) locks 20 % of the eligible buoys per region (seed 1199; the list and its SHA-256 are committed at freeze). No gate or diagnostic may read them before the LOCKED WINDOW (2027-03-01 to 2027-04-30), and an unlogged read voids the holdout. This lane's scorer published PUBLIC tables pooled over ALL buoys every day, so it would read the locked set daily.

| # | Rule | Ruling | Where it is built |
|---|---|---|---|
| B1 | Collection | **Unchanged.** The sampler and the daily truth snapshot archive EVERY listed buoy, locked or not (#1199: "LOCKED buoys still have archive records written"). | `served_wave_verify_sample.py`, `--snapshot-truth` |
| B2 | The scorer, its tables and its logs | **Changed.** Every reading mode goes through `holdout.state()`. Once READY, a locked station's truth snapshots are never downloaded or opened. Its records are dropped on load and dropped again inside `served_scorer.score` (two fences). The scores equal scoring with those buoys absent (tested against the golden fixture). `--publish` refuses any document that names a locked id. Every printed line (snapshot, download, score, verify) is redacted, because this repository's Actions logs are public. The weekly snapshot PR commits only a document whose status is `scored`. The score document records the locked list's SHA-256 and the count excluded, never the ids. | `point_archive/holdout.py`, `served_scorer.score(locked=…)`, `served_wave_verify_score.py`, workflow job `snapshot`; tests `test_served_wave_holdout.py` |
| B3 | Before #1199's list exists | **Changed.** While the buoy list's `holdout.locked_list` is null, the scorer is COLLECT-ONLY. `--download` reads nothing. `--score` writes a `NOT_READ` document (status, reason, list version; no window, no table, no id). `--publish` publishes nothing. A named list that is missing, does not hash to its recorded SHA-256, holds an unknown id, or disagrees with the stations' `locked` tags is also `NOT_READ`, and the job exits non-zero: the check fails closed. | `holdout.state`; same tests |
| B4 | Buoy list version 2 | **Changed.** Each station gains `fit_used` / `fit_used_by` (the consumers whose fits read it) and `locked` (null until #1199's freeze). The list gains a `holdout` block holding the `locked_list` pointer (null), the rule, and the fit-used census's path, date, canonical SHA-256 and open items. The list is exactly the version 1 freeze plus the committed census (`served-wave-verify-v1-fit-used.json`), reproduced by a test. **`buoy_list_hash` leaves out the two freeze-filled fields** (each `locked` tag and the `locked_list` pointer). Filling them at #1199's freeze changes no sampled byte, so it creates no new list version and does not split the archive's tables. A change to `fit_used` is a new version (tested). The integrity of the locked set is the locked list's own SHA-256. | `buoys.hashed_view` / `list_hash` / `validate`, `served_wave_verify_freeze_buoys.py --tag`; `test_served_wave_buoys.py` |
| B5 | Fit-used census (2026-11-23) | 26 of the 100 buoys are `fit_used`. **wave_emos_l1:** 17 listed buoys of the L1 panel (19 buoys, named 2026-11-16). **skill_ledger_fits:** 10 listed buoys of the 60 the skill ledger maps (`surf_spots.noaa_buoy_id`, read by one SELECT from the production database). Those 60 feed the debiased and weighted consensus, the MOS and OCF biases and the rolling bias correction being built. 51201 is in both. Files that mention a station but fit nothing (scoring, validation, archives, an admin picker) are listed as `not_a_fit` with the reason. **Open:** the wind / gust EMOS station set (`weather-products/calibration/emos/stations.json`, a private object this session was not permitted to read). Whoever freezes #1199 reads it and adds the consumer; that is a new census and a new list version. | `served-wave-verify-v1-fit-used.json` |
| B6 | Locked-list file contract | #1199's freeze writes `docs/weather-program/gates/served-wave-skill-v1-locked.json` = `{"gate", "seed": 1199, "fraction": 0.2, "stratified_by": "region", "drawn_from_buoy_list_hash", "locked": [ids]}`. Recording it means setting the list's `holdout.locked_list` = `{"path", "sha256"}` (the SHA-256 of the file's raw bytes) and each station's `locked` to match. The hash of the list does not change (B4). | `holdout.py` docstring |

**What this does not change.** No metric, bin, minimum n, tier, pooling rule or record field changes. `fit_used` buoys stay in this lane's indicative tables, tagged, and the document lists them (`holdout.fit_used_in_tables`). #1199's P1 excludes them by its own rule. The scorer version is now `served-wave-scorer/2`.

**Gating.** Collection may start on David's word once #1177 and this amendment have merged; the director sets `SERVED_WAVE_VERIFY`. Scoring and publishing start only when #1199's LOCKED list is frozen, committed and recorded in the buoy list as B6 describes. Until then every daily score run records `NOT_READ`.
