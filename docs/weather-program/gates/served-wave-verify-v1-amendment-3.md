# Amendment 3 to served-wave-verify-v1: the #1199 LOCKED fence, program-wide
Stamp: 2026-11-23. This is the director's P0 from the Fable inspection (SOTA-GAP-INSPECTION-2026-11-23, finding 2). Amendment 2 fenced the LOCKED holdout in one consumer, this lane's scorer. Every other module that reads buoy truth read every buoy: the skill ledger, buoy calibration, the accuracy monitor, gust verification, EMOS and the long-range wind truth. The list is still unrecorded (`holdout.locked_list` null), so no read has yet touched a locked buoy. Without this fix, the breach would start the moment #1199 freezes the list. This amendment lands BEFORE that freeze.

| # | Rule | Built |
|---|---|---|
| C1 | **One fence.** `backend/services/buoy_holdout.py` (stdlib only, so subprocess fetchers and `python -I -S` scripts can import it) reads the ONE record of the locked list: the served-wave buoy list's `holdout.locked_list` {path, sha256} and the stations' `locked` tags. It verifies the list file's SHA-256. `point_archive/holdout.py`, the strict wrapper the served-wave scorer uses, now verifies through it, so there is one implementation. | `services/buoy_holdout.py`, `point_archive/holdout.py` |
| C2 | **Three states.** `none` (no list recorded, today): an exact no-op; every consumer behaves as before. `verified`: the locked ids and their aliases. A recorded list that does NOT verify (missing, hash mismatch, unknown or duplicate ids, tags that disagree, unreadable buoy list) gives `quarantine`: **fail closed without crashing.** Every listed buoy, with every alias, is treated as locked, and the reason goes once to stderr. No second copy (such as the tags alone) is trusted (Reflection, 2026-11-23). The strict scorer goes NOT_READ as before. | `buoy_holdout.state()` |
| C3 | **Aliases** (SubQ, Reflection): the station id, the WMO id and, for a CDIP buoy, CDIP's own station number (`cdip_id`, else the "(NNN)" NDBC's station table writes in its name). `106p1` reads as `106`. | `_aliases`, `_norm`; test over all 10 committed CDIP buoys |
| C4 | **Applied at load, before any aggregation or join** (SubQ). `allow_url(url)` gates every fetch path at runtime, so a URL built at runtime is caught too. It matches a locked id standing alone in the path or query, or followed by NDBC's `h<year>` or CDIP's `p<n>`. `drop(rows, key)` and `keep(id)` act on loaded derived rows (scored ledger months, residual history, gust/EMOS/wind-lr tables, caches, result files) and on station loops. `redact(text)` covers what is printed, since Actions logs are public. 54 modules call the fence. | the consumer edits in this PR |
| C5 | **Collectors keep collecting** (#1199: locked buoys are still archived for the LOCKED WINDOW). Five modules declare themselves with `declare_collector` and redact what they print, but skip no buoy: `served_wave_verify_sample`, `gust_verify_collect`, `wind_emos_collect`, `wind_lr2_collect` and `sst_collect`. The served-wave truth snapshot (`--snapshot-truth`) also archives every listed buoy. | |
| C6 | **Guard (static).** `tests/test_buoy_holdout_guard.py` scans every backend module for buoy-truth access: NDBC or CDIP realtime/archive hosts and paths, the shared truth fetch and parse helpers, and the derived stores (the skill ledger, gust verification, EMOS, the point archive). It fails on any module that neither calls the fence nor declares itself a collector, unless the module is in a reviewed EXEMPT list (14 entries, each with its reason). An exempt module may hold no buoy-observation URL, a stale exemption fails, and no workflow may `curl` or `wget` a buoy host. | test file |
| C7 | **Canaries (runtime).** `tests/test_buoy_holdout_consumers.py` plants a VERIFIED locked list. Six real consumers, one from every family, then never request a locked buoy or drop its rows at load, while an open buoy passes untouched: calibration fetch, scored-archive read, eval-harness GET, long-range wind truth, partition spectra, gust scorer. With no list, nothing is dropped. Mutation checks (allow_url forced open, drop made a no-op, one consumer's gate removed, aliases off) each turn them red. | test file |

**Known limits** (written down, not hidden):
- **Caches read by name.** A script that reads a buoy file someone cached earlier by bare name, with no URL or store prefix the guard knows (as `jac1_mop_calibration/analyze.py` and `losers.py` did; both are now fenced), is invisible to the static guard. The runtime gates cover the fetch, not a hand-copied file.
- **The skill ledger stops collecting locked buoys after the freeze.** `buoy_calibration.fetch_ndbc_latest` is gated, so once the list is recorded the ledger neither scores nor archives locked buoys. Rows already archived stay, and every read drops them. If the LOCKED WINDOW needs ledger-format rows, a collector must archive them; the served-wave archive and its truth snapshots do so for waves.
- **Future station freezes see a locked buoy as having no data.** A new long-range-wind freeze after the list is recorded reads truth through the fenced window and will leave locked buoys out. Lists already frozen are unchanged.
- **The spot-to-buoy mapping keeps locked buoys.** `map_spots_to_ndbc_buoys.py` refuses their URLs and redacts its output, but keeps them in the mapping it writes, because the mapping is not a score.
- **Other lanes.** The EMOS lane's unpushed `gust_calibrate.py` carries its own `--exclude-stations` SHA check; it will switch to this fence once this merges (that lane, 2026-11-23). The long-range-wind lane's open #1215 / #1216 touch nearby files. The guard will flag any new reader they add.

**LongCat review (2026-11-23, after the SubQ and Reflection consults).** It made five findings; three held up and are fixed:
- When the buoy list is unreadable, `redact` now blanks every token shaped like a buoy id. It used to blank none.
- The guard now counts only a real call of the fence, checked by parsing the file. A mention in a comment or docstring no longer satisfies it.
- A locked-list path that is rooted, or that climbs out of the repository, now quarantines. It used to be read.

Two were refuted from the code:
- CDIP buoys carry both their NDBC id and their CDIP number, so "a CDIP buoy keyed by its NDBC id escapes" does not happen.
- `allow_url` already catches `<id>p1` and `<id>_...` URLs.

Its suggestion to also watch the CDIP thredds host was checked. The only modules that use that host outside the fenced ones read MOP **model** hindcasts (`jac1_mop_calibration/locate.py`, `rating_truth_mop.py`, `swell_exposure_normals_fit/measure_normals.py`), not buoy observations, so they are out of scope.

**Gating.** No served number moves, and no behaviour changes while no list is recorded. The fence acts only when #1199's freeze records the list in the buoy list (amendment 2, B6), and after this merges.
