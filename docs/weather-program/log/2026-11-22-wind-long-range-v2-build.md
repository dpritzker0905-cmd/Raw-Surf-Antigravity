## Station freeze, reading (b) (advisor ruling 2026-11-23T12:45:02Z) - written BEFORE any TEST data
Binding reading, fixed here so it cannot be chosen later: **coverage is a SCORE-time report, never a row filter and never a freeze filter.**
- The frozen list is everything that passes the CATALOGUE rules of the old registration as of 2026-11-22: NDBC/C-MAN `met=y` buoy/fixed within 50 km of GFS land with a known anemometer height; IEM ASOS within 10 km of GFS sea, at most 60 nearest the sea (ties by id); duplicated ids counted once. No hourly-coverage test runs at freeze and no observation file is read (`wind_lr_obs.select_stations(coverage_filter=False)`, pinned by tests that make every coverage and observation reader raise). The old freeze files of runs 44376282465, 43952101715 and 44107750669 are never read or reused: `wind_lr2_stations.py` builds fresh from the live catalogues and refuses an old freeze file or an existing output. It is the only writer of `docs/weather-program/evidence/wind-long-range-v2/wind_lr2_stations.json` (the analyse workflow's `stations` command no longer calls `wind_lr_hindcast.py stations`).
- The list records the registered date (`asof` 2026-11-22) and the UTC date the catalogues were actually read (`read_at`); region labels are the amendment-A3 ordered rules; the marine-exposed flag and the spot pairing are the later `pair` step. Its sha256 is written beside it and goes into the committing PR.
- At SCORE time (`wind_lr2_truth.coverage_report`, written into the result as `station_coverage`): each station's hourly coverage over the TEST valid window is computed, WSPD+WDIR for wind and GST separately, and reported per station. The 70% threshold is used for exactly two things: the floor counts (>= 10 marine-exposed stations per region in >= 3 regions; the gust floor counts GST coverage) and the report. It never drops a row: every frozen station's paired rows are scored, so missing hours drop out for all arms alike.
Disclosure: the catalogue is read live, so the list reflects the catalogues on the run date; `read_at` records that day.
## Gust truth build change (amendment G1, PR on top of #1142)
Changed the CODE, not the registration: `wind_lr2_rows.station_truth_fn` now builds the gust truth as amendment G1 fixes it: the 6 h window max of NDBC GST (each hour the report nearest the hour within +-10 min, all six present, none filled), adjusted to 10 m by the log law, only at NDBC stations with 1 m <= z <= 50 m. ASOS stations, and NDBC stations outside that height range, carry NaN gust, so they are outside the GF fit and the gust score. This removes `gust_absent_is_wind` (an absent ASOS gust imputed as the wind, which censored gust truth low) from the v2 path; the older `wind_lr_obs.gust_window` is untouched (the #939-era scorers still use it). On the GF mismatch the gust-labels lane found: registration section 2 said "member median of the arm's gust"; `wind_lr2_fit.fit_cell` fits `median(observed gust / calibrated speed)`. Amendment 1 A4 had already changed the REGISTRATION side to the code's form (one definition for every arm, AIGEFS included), so the code stays and the doc was already the side that changed; amendment G1 now fixes which observed gust it is. 8 tests in `test_wind_lr2_gust_truth.py`.
