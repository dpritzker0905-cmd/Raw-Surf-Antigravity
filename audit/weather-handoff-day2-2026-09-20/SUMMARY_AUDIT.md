## Repairs and causal evidence

**1. Unresolved wave directions could become authoritative surf inputs.** Opposing height-weighted vectors produced arbitrary bearings. In the actual backend point → canonical surf transform → rating probe, a GFS-height perturbation of only ±`1e-8 m` changed direction to 180°/0° while rounded offshore height stayed 2.4 m; surf height changed from 1.962 to 3.2975 m and rating from 6.8 to 68. Missing bearing arrays also manufactured north, and nonfinite bearings could produce invalid outputs.

The backend now requires finite direction support for active positive-height contributors, excludes an unusable optional ICON bearing using the existing source fallback policy, and refuses numerically cancelling resultants. Point refusal reaches the existing labeled coarse fallback or 404; grid/lattice refusal marks invalid cells and rejects wholly invalid products. Calm and healthy north/wrap-around controls remain valid. **57 new backend controls** include real HTTP fallback behavior. [Backend finding and repair](DIRECTION_FINDING_AND_REPAIR.md)

**2. Frontend ICON mirrors bypassed the repaired backend estimate.** Actual point/grid calls reproduced the same cancellation defect. The frontend now shares a small checked blend module, honors source masks, preserves missing native values, and carries refusal through extended-point, secondary-swell and grid-continuity paths. A second review caught and fixed a mapper bypass where an explicit placeholder bearing hid cancelled components. **43 new frontend controls** cover these paths. The reachable infobox defect is demonstrated; these mirrors' rating gates do not support claiming corrupted surf glyphs from this probe. [Frontend repair](FRONTEND_DIRECTION_REPAIR.md)

**3. Raster fallback could select the wrong forecast cycle or hour.** On a cold request the app returned bootstrap metadata immediately and intercepted `latest.json` with a fabricated completed manifest. The installed decoder cached the guessed 06Z cycle even when the real provider cycle was 12Z. Awaiting and preserving validated provider metadata fixes that defect. A further mounted-hook test found that failed initial metadata could still choose an index on the bootstrap axis; a later real provider response decoded 21Z for a requested 15Z. The hook now emits transparent slots until authoritative metadata is available and recovers on a normal retry. **13 new metadata controls**, including real decoder/cache and mounted-hook tests, cover both failures. The provider host is unchanged. No live pixel, halo, provider-host availability or 1-FPS closure is claimed. [Raster evidence](fallback-triage.md)

## Jacobian interpretation and research check

For a circular mean, angular sensitivity grows inversely with the resultant magnitude. At cancellation the bearing is undefined, so passing its floating-point residue into directional exposure can yield a discontinuous rating change. The dimensionless `R <= sqrt(machine epsilon)` guard is an arithmetic-conditioning policy; it is not a calibrated directional-spread threshold. Real source uncertainty and quantization are larger and still need observation-based evaluation.

This is consistent with [SciPy's circular-mean contract](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.circmean.html), which documents implementation-dependent output when the mean resultant is zero. Supabase's [Storage error-code documentation](https://supabase.com/docs/guides/storage/debugging/error-codes) distinguishes object absence from bucket/tenant failures and warns that absence responses can also reflect access; the archive repair therefore requires guarded creation rather than blind upsert after a missing read. Forecast verification continues to use common observations, consistent with [ECMWF's wave-verification practice](https://www.ecmwf.int/en/newsletter/150/meteorology/twenty-one-years-wave-forecast-verification).
