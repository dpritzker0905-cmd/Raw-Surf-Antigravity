## 0. Executive summary — the four mechanisms that matter

1. **The weather simulation engine can be shut down and never restarted.** The bootstrap effect's cleanup calls `shutdownEngine()`, but the re-entry guard reads the *init-sequencer state* (which `shutdownEngine` does not reset) instead of the *engine's own `_initialized` flag*, so the re-run short-circuits and `initEngine` is never called again. This is the single highest-value lead for "frozen animation / stale timeline / buffer not updating".
2. **`window.isScrubbingTimeline` is a bare global read at 60+ sites** that gates marine fetch, wind fetch, tile URL resolution, field binding, commit, and repaint. It is written in exactly one component. There is at least one confirmed code path (unmount mid-gesture) that leaves it stuck `true`, which would freeze the entire pipeline at once.
3. **The marine animation is self-driven by `map.triggerRepaint()` placed *after* `engine.render()` inside a `try`** — one render exception drops the repaint chain, and after 3 errors the log goes silent.
4. **A stale `localStorage.__BACKEND_URL__` silently outranks `REACT_APP_BACKEND_URL`** and is frozen at module-import time. Any live measurement must clear/verify this key *first* or the whole session may be reading a different backend than the brief assumes.

**Leads that are genuinely resolved and should not be re-chased:** upside-down/half-screen antimeridian fields, wrong particle direction across ±180, DPR/half-res blur, service-worker-served stale weather payloads, per-frame React commits, StrictMode double-init, unstable dep arrays in the map path.

## 4. WHAT I COULD NOT ESTABLISH (be explicit)

- **D-01 / D-02 consequence.** I established the *code shape* beyond doubt (shutdown runs, restart short-circuits). I did **not** establish that `userTier` actually transitions after `mapInstance` exists on a real load. Effect ordering favours the *safe* case on a cold reload (React runs descendant effects before ancestor effects, so `AuthProvider`'s synchronous `setUser` at `AuthContext.js:70` likely lands before MapLibre's async `load` sets `mapInstance`). The realistic trigger is an **in-app navigation to `/map`** (where `MapPage.js:44-51` fires `refreshUser()` → async `setUser` at `AuthContext.js:170`) or an explicit login/logout while the map is mounted. **Only the live run can settle it.**
- **D-09 (NY / Portugal / Spain / Morocco dead zones).** I could not find a mechanism that predicts *those specific* longitudes. Anything I wrote would be a guess. The live run must localise first.
- **TDZ repo-wide (D-11).** Module-concatenation ordering is a webpack build property; I read source, not the emitted bundle. I verified only that the two boot-critical modules hold the `var`-only convention.
- **`__RAW_*` completeness.** 465 globals is beyond exhaustive verification in this pass. §2 covers every *callable* hook and every diagnostic I read the assignment site for. The remaining ~380 are predominantly single-purpose kill switches in the `__RAW_*` family.
- **Frontend/production divergence.** Production frontend is the frozen Netlify shell at `3bd38a83` (2026-05-20). **Nothing in this document describes production frontend behaviour** — it describes this tree, i.e. the local dev surface only.
