# G12.2-MU-01 — `fetchModelMetadata` arity mismatch — VERDICT: PROOF_FAILED

Auditor: independent refutation pass. Repo `C:\Users\dprit\Raw-Surf`, branch `dev`, HEAD `791fdf78`.
READ-ONLY on all production source. No commits, no dispatches.

## The claim

> `fetchModelMetadata` is called with a fourth abort-signal argument it does not accept, so the
> `om://` metadata fetch is unabortable. `useOpenMeteoTileUrls` passes an AbortSignal as a fourth
> argument into a three-parameter function; JavaScript silently drops it, so the model-metadata
> fetch that pins the raster lane's run identity for the whole page cannot be cancelled on unmount,
> model switch or navigation.

## 1. What reproduces at HEAD

The **arity mismatch itself is real**. Both cited lines are accurate:

- `frontend/src/components/map/mapUtils.js:345`
  `export async function fetchModelMetadata(modelToCheck, MODEL_METADATA_CACHE, onMetadataChanged) {` — 3 params.
- `frontend/src/components/map/useOpenMeteoTileUrls.js:363-370` — the wrapper forwards a 4th argument `signal`.
- `mapUtils.js:348` — the inner `fetch(...)` passes no `signal` option. Confirmed.

## 2. What does NOT reproduce — the load-bearing half

**No AbortSignal is ever passed. The 4th argument is `undefined` on 100% of invocations, repo-wide.**

Repo-wide census of every reference (command run verbatim):

```
git grep -nE "fetchModelMetadata|fetchMetadata" -- .
```

10 hits total. After removing the definition (`mapUtils.js:345`), the import
(`useOpenMeteoTileUrls.js:12`), the wrapper definition (`:363`, `:364`), a `useCallback` dep array
(`:380`), a `useEffect` dep array (`:687`), a mermaid node in `docs/architecture/weather-engine.md:16`
and a prose mention in a 2026-07-16 handoff, there are exactly **two invocation sites**:

- `useOpenMeteoTileUrls.js:379` — `allModels.forEach(m => fetchMetadata(m));`
- `useOpenMeteoTileUrls.js:545` — `await Promise.all(models.map(m => fetchMetadata(m)));`

Both pass **one** argument. `signal` is therefore always `undefined`.

Positive control for the search technique (same tool, same scope, token known to be widespread):
`git grep -cn "MODEL_METADATA_CACHE" -- frontend/src` returns 10 files with counts 1–8. The
technique finds what is there.

Second control — the accidental-index path is also closed. Both call sites use **arrow wrappers**,
so `forEach`/`map` cannot leak their index into argument slot 2 of the wrapper:

```
node -e "const w=(m,s)=>({m,s}); console.log(JSON.stringify(['a','b'].map(w))); console.log(JSON.stringify(['a','b'].map(m=>w(m))));"
point-free:     [{"m":"a","s":0},{"m":"b","s":1}]     <- would be a real (benign) bug

```

Execution proof replicating the exact HEAD shapes:

```

wrapper('ncep_gfs025') -> { argsLen: 4, fourthType: "undefined", isSignal: false }
```

`argsLen: 4` confirms the extra argument is delivered; `fourthType: "undefined"` confirms it carries
nothing. There is no cancellation intent anywhere in this path for the arity to defeat.
Grepping `AbortController|AbortSignal|\.abort\(|signal:` across `frontend/src/components/map` returns
60+ hits — none of them constructs or routes a controller for the model-metadata path.

## 3. Provenance — how the mismatch got there

`git log -S "onMetadataChanged, signal" -- frontend/src/components/map/mapUtils.js`

- `5ebc8b46` (2026-05-24, *"implement resilient client fallback and precise abort signals
  synchronization"*) — introduced the 4-param version. It **did** use the signal: an early
  `if (signal?.aborted) return Promise.reject(...)` guard plus `{ signal }` on both the proxy fetch
  and the CDN fallback fetch.
- `de351a46` (*"refactor(loc): modularize all high-warning components and utilities to sit strictly
  under 800 LOC limit"*) — dropped `signal` from the callee, and with it the aborted-guard and the
  proxy/CDN-fallback pair. The caller's forwarding was left in place.

So this is an **LOC-ratchet refactor residue** — the same class MEMORY records as
"THE LOC RATCHET MEASURES OUR DOCUMENTATION". Nothing about it was ever exercised after `de351a46`,
because no caller had ever supplied a signal.

## 4. Why the implied fix is contraindicated

`useOpenMeteoTileUrls.js:372` labels the site: *"Pre-warm ALL model metadata immediately upon mount
to eliminate layer activation latency completely."* This codebase has a **tested, root-caused rule
that background prewarms must NOT carry an abort signal**:

- `marineGlobalPrewarm.js:141` — *"No abort signal: this is a background best-effort warm that must
  survive the pan/zoom which would otherwise cancel it."*
- `marineController.globalSeriesPrewarm.test.js:54` — `expect(signal).toBeUndefined();  // no abort
  signal: it must survive the pan that follows` — an **enforced** assertion.
- `useMarineOrchestrator.js:868-873` — a live-confirmed production incident (2026-06-26, the
  *"scrub never gets snappy"* root) caused by a cleanup's `controller.abort()` killing an in-flight
  prewarm.

Architecturally the same conclusion holds. `MODEL_METADATA_CACHE` is an imported module-level
singleton (`useOpenMeteoTileUrls.js:24`) handed to `registerOpenMeteoProtocol` at `:331`, and read by
the `om://` protocol interceptor at `openMeteoProtocol.js:445-467` — a maplibregl-global handler that
outlives every component. `fetchModelMetadata` also dedupes module-wide via `MODEL_METADATA_PROMISES`
and `LIVE_FETCHED_MODELS` (`mapUtils.js:342-343`). Aborting on one component's unmount would starve a
consumer that is not component-scoped and would kill a promise other consumers deduped onto.

## 6. Adjacent observation (NOT this gap, not inflated into one)

`fetchModelMetadata` stores the in-flight promise in `MODEL_METADATA_PROMISES` but returns
`cached || { variables: [], validTimes: [], referenceTime: null }` at `mapUtils.js:385` **without
awaiting it**. Consequently the `useOpenMeteoTileUrls.js:543-547` block commented
*"Asynchronous slow-path (only used if cache is cold)"* — `await Promise.all(models.map(m => fetchMetadata(m)))`
— does not actually wait on a cold cache; it resolves on the next microtask with empty metadata. It
self-heals via the `metadataRevision` bump (`:367` → dep at `:687`). This is a comment-vs-code
discrepancy in the same family the other auditor filed as G12.2-WSW-01 (never-invalidated cache), and
belongs there if anywhere. Recorded here only so it is not lost; it is **not** the claimed defect and
it is **not** fixed by changing the arity.

## Reopen criterion

This is re-openable only on evidence that a real `AbortSignal` reaches
`useOpenMeteoTileUrls.js:363` at runtime — i.e. a third call site passing two arguments, or a
console/network trace showing a metadata request that a lifecycle teardown intended to cancel and did
not. Neither exists at `791fdf78`.
